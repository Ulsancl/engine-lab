# Engine Lab 첫 공개판의 범위

이 문서는 일반 사용자가 엔진을 관찰하고 실험하는 첫 공개판의 완료 기준이다. 실제 검증 여부와 확인한 환경은 각 릴리스의 결과 기록을 따른다. 문서나 CI 파일이 존재하는 것만으로 해당 릴리스의 검증·공개가 완료되지는 않는다.

첫 공개판은 자체 제작한 대표 직렬 4기통 DOHC 가솔린 엔진 하나를 다룬다. 선택 실린더 확대, 조립·절개·분해, 부품 선택, 720° 각도 이동, 회전수·재생 배율·흡기 위상 조절, 관찰 상태 저장이 제품 범위다. 첫 사용자는 한 사이클을 보고 크랭크 두 바퀴와 캠 한 바퀴, 같은 피스톤 높이와 서로 다른 행정, 흡기 위상에 따른 밸브 오버랩의 차이를 직접 확인할 수 있어야 한다.

## 공개 후보의 완료 기준

| 항목 | 완료 조건과 남길 근거 |
|---|---|
| 계산과 단위 | `npm test`가 통과한다. 로드 길이·행정·실린더 위상·캠 비율·밸브 이벤트·접촉·간섭의 기하학적 기준, 시간 분할과 주기 각도 경계, 파일 상태 복원이 독립 기준과 일치한다. 설정 rpm과 화면 rpm, 크랭크각과 캠각을 설명에서 구분한다. |
| 관찰 경험 | 브라우저 조작 검사와 실제 화면 검토를 함께 수행한다. 단기통/4기통, 절개/분해, 정면/측면/사시점에서 주요 부품을 식별하고 이름표를 읽을 수 있다. 분해 형상이 프리셋 시야 밖으로 잘리거나 안내 배지가 이름표를 가리지 않는다. 좁은 브라우저 화면에서도 관찰 영역과 핵심 조작을 사용할 수 있다. |
| 사용자 조작 | 수동 각도 이동과 선택 실린더의 행정 이동이 일치한다. 흡기 진각은 열림·닫힘을 앞당기고 오버랩을 바꾸며, 밸브 곡선·수치·선택 실린더의 실제 리프트가 같은 상태를 설명한다. 선택·시점·분해 조작은 기구 위상을 바꾸지 않는다. 새 실험 시작 뒤 이전 관찰로 돌아갈 수 있다. 8초 안내는 전경에서 한 사이클 뒤 멈춘다. 자동 시간 검사와 실제 전경 창의 경과시간을 구분해 기록한다. |
| 실험 보존 | 설정·배율·각도·선택·레이어·시점이 파일과 재시작 후 복원된다. 취소·잘못된 파일·새 버전 파일·크기 제한·손상된 자동 저장을 처리할 때 사용자의 원본을 잃지 않는다. 네이티브 대화상자가 열려 있는 중 종료와 반복 창 복원도 검사한다. |
| Windows 배포 | 소스 앱과 독립 실행파일의 네이티브 검사를 통과한다. 이어 최종 설치파일을 실제 Windows x64에 설치해 아이콘 실행·오프라인 관찰·저장·재시작을 확인하고 기존 0.1 사용자 데이터를 유지한 업데이트를 검사한다. 테스트는 임시 사용자 저장소에서 수행한다. 확인한 OS·앱 버전·그래픽 환경·결과를 해당 후보의 증거에 남긴다. |
| 출처와 재현 | 승인한 소스의 고정 의존성으로 새 빌드를 만들고 배포 빌드와 대조한다. 패키지의 소유 파일·버전·문서·외부 고지·설치파일 SHA-256이 일치한다. 새 후보 검사 때문에 보존된 이전 버전의 원본·설치파일·검증 근거를 덮어쓰지 않는다. |
| 공개 확인 | 공개할 정확한 소스 커밋에서 CI가 통과하고 설치파일·체크섬·변경 내용이 그 후보와 연결된다. 배포 후 실제 공개 링크와 파일 해시를 확인한다. CI는 검증 파일을 보관하며 릴리스를 자동 게시하지 않는다. |

이 기준은 지정한 제품 범위와 공개 후보를 완료하는 기준이다. 모든 하드웨어를 검사하거나 다른 엔진 형식·열역학·정비 도구를 추가해야 완료되는 목표로 확장하지 않는다. 이전 버전에서 통과한 결과를 변경된 후보에 그대로 적용하지 않으며, 후보의 시험 결과와 실제 제한을 함께 기록한다.

## 현재 모형의 한계

- 운동학 입력 rpm으로 강체 기구를 구동한다. 연소가 만든 rpm·토크·출력·압력·온도·연비·배출가스·노킹·진동·수명은 계산하지 않는다.
- 고정 치수의 교육용 엔진이다. 제조사 CAD나 특정 차량 엔진의 공차·설계·정비 절차를 재현하지 않는다. 단기통 모드는 같은 엔진의 한 실린더 확대다.
- 밸브 프로파일은 최대 6 mm의 교육용 `sin²` 함수다. 끝점에서 리프트와 기울기는 연속이지만 가속도까지 연속인 실제 제작용 캠이라고 주장하지 않는다. 스프링 서지·밸브 바운스·체인 탄성·마모·유압 위상 조절의 과도응답은 다루지 않는다.
- 점화 불빛·행정 색·오일 이동점은 순서와 경로의 설명이다. 오일 압력·유량·유막이나 실제 가스 유동을 표시하지 않는다. 분해는 구조 관찰을 위한 위치 이동이다.
- 높은 화면 rpm에서는 프레임 샘플링으로 회전 방향이나 짧은 이벤트가 다르게 보일 수 있다. 정밀한 위치 관찰은 일시정지·저속 재생·수동 각도 이동을 사용한다.
- 현재 배포 대상은 Windows x64이며 코드 서명과 자동 업데이트는 없다. 다른 운영체제 설치판과 모든 GPU 조합의 호환성을 보증하지 않는다. 이 검증은 실제 엔진의 설계 승인·정비 진단·성능 보증이 아니다.

## CI와 버전 관리

`.github/workflows/ci.yml`은 Windows에서 `npm ci` → 순수 검사 → 빌드 → 브라우저 조작 → 소스 네이티브 검사 → 설치파일 패키징 → 독립 실행파일 검사 → 체크섬·필수 문서 확인 순으로 실행한다. 브라우저 검사는 자체 로컬 Vite 서버와 Chromium을 사용하고, 네이티브 검사는 별도 임시 앱 저장소를 사용한다. CI에서 그래픽 컨텍스트가 동작하는 것과 사용자의 실제 GPU 환경을 확인하는 것은 구분한다.

버전만 바꿀 때는 `package.json`의 `version`, `package-lock.json`의 최상위 `version`과 `packages[''].version`만 같은 제품 버전으로 갱신한다. 모든 일치 문자열을 치환하면 우연히 같은 버전의 의존성을 손상시킬 수 있으므로 금지한다. 의존성 변경이 없다면 이 제품 메타데이터 외 lock 구조가 이전 승인본과 동일한지 대조한다.

참고 원리와 자산 범위는 [참고 자료](references.md), 정확한 수식·단위·밸브 타이밍은 [계산 모형](model.md)을 따른다.
